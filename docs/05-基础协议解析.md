# 基础协议解析

## 已实现

代码位置：`src/packet/packet.h` 定义捕获记录，`src/parser/packetparser.*` 实现独立于 GUI 的解析器。

| 层次 | 当前支持 |
| --- | --- |
| 捕获链路 | Ethernet、最多四层 VLAN、Linux SLL/SLL2、NULL/LOOP 回环头、RAW IP、专用 IPv4/IPv6 链路类型 |
| 网络层 | IPv4 可变头长、IPv6 固定头与常见扩展头、Ethernet/IPv4 格式 ARP |
| 传输层 | TCP 可变头长、端口、原始序列号/确认号、标志、窗口与载荷长度；UDP 端口和载荷长度 |
| 控制消息 | ICMP/ICMPv6 类型和代码；Echo 请求/应答的标识符和序号 |

列表增加源地址、目的地址、协议和摘要。未知协议、截断包和异常长度在摘要中标记；列表列宽可拖动，完整内容可悬停查看。

## 解析规则

1. 首先按捕获记录的链路类型确定网络层起点，不统一套用 Ethernet 的 14 字节偏移。
2. 逐层检查版本、最小头长、声明长度和实际捕获长度。
3. IP 声明范围以外的填充不作为传输层数据解析。
4. IPv4 非首片与 IPv6 非首片只显示网络层信息和分片标记，不从分片载荷猜端口。
5. 首片可以解析当前完整可见的传输层头，但不做 IP 分片重组；头部跨分片时标记需重组。
6. IPv6 扩展头遍历最多 16 次，支持 Hop-by-Hop、Routing、Destination Options、AH 长度遍历和 Fragment；ESP 载荷保持不透明。
7. 保留协议集合，例如 Ethernet/IPv4/TCP，方便后续按不同层次筛选。

解析状态包括完整、暂不支持、截断、格式异常。这里“完整”只表示已实现字段通过本解析器的结构检查，不代表校验和、协议全部语义或整个连接内容都经过验证。

## 当前边界

- 不做 IP 分片重组和 TCP 流重组。
- 不根据端口将 TCP/UDP 误标为 HTTP、DNS、TLS 等应用协议。
- 不校验校验和，避免将本机网卡卸载造成的捕获表现直接判成网络错误。
- IPv6 巨型报文不深入解析，未知链路/协议保留捕获记录并明确标记。
- ICMP 错误消息当前展示类型和代码，尚不递归解析其引用的原始 IP 包。
- 此阶段仅新增列表字段，协议详情树和原始字节窗格留待下一阶段。

## 验证

```bash
cmake -S . -B build
cmake --build build -j2
ctest --test-dir build --output-on-failure
./build/netsniffer
```

测试包括已知地址和端口、VLAN、SLL/SLL2、回环头、IP/TCP options、IPv6 扩展头、IP 分片、ARP、全部样例前缀截断、非法长度以及 4000 组确定性随机输入。界面测试通过辅助程序管道输入已知 TCP SYN，核对显示的地址、协议、长度和摘要。

人工验证可在普通权限下启动已安装辅助程序的 GUI，选择实际网卡或 `lo`/`any`，产生 ping、HTTP 等流量，再与 Wireshark 对同一流量的字段进行对照。HTTP 流量在这个阶段仍显示 TCP，这是预期行为。

本阶段不修改辅助程序或 IPC 协议，无需重新安装抓包辅助程序。
