# PCAP 保存与离线读取

## 使用步骤

1. 停止实时抓包。
2. 点击“保存缓存”，选择输出位置，保存为 `.pcap`。
3. 点击“打开 PCAP”，选择已有文件。
4. 继续使用协议/IP/端口显示过滤、详情树、Hex/ASCII 和字段字节高亮。

文件读写期间提供“取消读写”按钮。打开、保存和实时抓包互斥；关闭窗口会请求取消后台读写，待工作线程退出后关闭。

离线读取不需要抓包权限、已安装的辅助程序或可用网卡。本阶段不修改辅助程序，不需要重新安装或授予权限。

## 保存范围

保存当前缓存中的全部包，包括被显示过滤隐藏的记录；表格排序不改变文件中的捕获顺序。

- 缓存同时受 2000 包和 64 MiB 原始字节上限约束。
- 导出只包含尚在缓存中的记录。
- 读取大文件会统计全部记录，但只保留符合缓存预算的末尾记录。
- 离线列表保留记录在源文件中的序号，例如 100000 个包的文件只缓存最后 2000 个时，列表从 98001 开始。
- 重新导出的文件只包含这些保留的记录，重新打开后按新文件的记录顺序重新编号。

## 文件内容与时间

使用 libpcap 读写经典 PCAP 格式，支持单一链路类型。PCAPNG 不属于本阶段的导入格式。不同链路类型不能混写到同一个 PCAP 文件。

保留以下记录信息：

- 原始捕获字节。
- 捕获长度与线上原始长度，允许前者小于后者。
- libpcap 链路类型。
- 微秒或纳秒时间戳。

导出采用纳秒精度的 PCAP 格式。数据结构在 `timestampUs` 外保留 `timestampSubMicroNs`（0–999），避免读入纳秒文件时丢失微秒以下的部分。

实时抓包仍以六位小数显示；导入的时间若包含非零的微秒以下部分，则显示九位小数。时间戳表示的时刻不因保存与重读而改变。

单包捕获长度和文件声明的 snapshot length 上限为 256 KiB，与普通链路的 libpcap 读取上限保持一致；超过范围返回错误，不分配不受限制的内存。经典 PCAP 的秒字段使用 32 位非负数，导出前校验可表示范围。

## 错误与取消

- 读取在后台完整验证源文件，成功后才替换界面数据。
- 文件损坏、打开失败或取消读取，原有列表、筛选和选中包详情继续保留。
- 保存前校验记录的长度、链路类型和时间戳。
- 使用 `QSaveFile` 临时文件配合 libpcap dumper，成功刷新后原子提交。
- 保存失败或取消不会以半成品覆盖已有目标文件。
- 文件对话框在补齐 `.pcap` 扩展名后处理覆盖确认。
- 输入只接受普通文件；错误信息显示在状态栏，不弹出开发说明。

## 代码位置

- `src/storage/pcapfile.*`：读写、输入边界、时间精度、原子保存与缓存预算。
- `src/storage/pcapfileworker.*`：后台读写、取消和进度。
- `src/packet/packet.*`：捕获记录与统一的时间格式化。
- `src/ui/mainwindow.*`：文件按钮、会话切换、导出快照及离线数据展示。

文件导入和实时抓包共用 `appendPackets()`，因此协议解析、缓存淘汰、显示筛选和详情查看采用同一套逻辑。

## 验证

```bash
cmake -S . -B build
cmake --build build -j2
ctest --test-dir build --output-on-failure
./build/netsniffer
```

新增测试：

- `pcapfile_check`：原始字节和长度往返、微秒/纳秒、大小端独立样例、RAW 链路类型、损坏文件、错误路径、非法记录、取消、原子保存、最大单包与缓存预算。
- `pcap_ui_check`：加载后筛选与高亮、排序后保存、隐藏记录导出、读取失败保留旧数据、实时/离线切换、后台取消、无网卡读取、大文件尾部缓存与关闭窗口。

导出文件已使用系统 tcpdump 独立读取验证；读写模块及新界面流程通过 AddressSanitizer/UndefinedBehaviorSanitizer 检查。界面布局通过离屏预览检查。
