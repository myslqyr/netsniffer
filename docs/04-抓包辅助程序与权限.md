# 抓包辅助程序与权限

## 1. 当前实现

程序已拆成独立的界面进程和抓包辅助进程，类似前后端分工，但通信发生在本机，不启动 HTTP 服务，也不监听网络端口。

```text
普通用户启动 build/netsniffer
    ↓ 点击开始
CaptureWorker 工作线程通过 QProcess 启动固定位置的辅助程序
    ↓ 传入 --interface 网卡名（独立参数，不经过 shell）
/usr/local/libexec/netsniffer/netsniffer-capture
    ↓ libpcap 打开设备后放弃所有运行中的 capabilities
    ↓ stdout 私有管道：就绪帧、数据包帧、错误帧
CaptureWorker 校验并解码 → 有界队列 → GUI 表格
```

- GUI 仍通过 libpcap 枚举设备，但不再打开抓包设备。
- 只有辅助程序具有 `cap_net_raw=ep` 文件权限，不授予 `cap_net_admin`、setuid root 或免密 sudo。
- 辅助程序不依赖 Qt，不负责协议分析，不接受文件输出路径或任意命令。
- 辅助程序是按需运行的子进程，不是常驻系统服务；每次开始创建，停止时退出。
- 生产运行固定调用安装路径，不自动执行工作目录中的同名文件。

## 2. 一次安装

先构建：

```bash
cmake -S . -B build
cmake --build build -j2
```

从日常开发用户的终端执行：

```bash
sudo bash scripts/install-capture-helper.sh
```

脚本执行以下工作：

1. 检查构建结果和 `setcap/getcap`。
2. 安装辅助程序到固定位置，由 root 拥有。
3. 设置为 `0750`，仅 root 和执行 sudo 的用户的主组成员可执行。
4. 仅向安装副本授予 `cap_net_raw=ep`。
5. 清除旧版 `build/netsniffer` 上可能残留的 capabilities。

这里使用开发用户的主组，因此无需新增用户组、注销或重新登录。若该主组与其他用户共享，这些组成员也能运行辅助程序；多用户正式部署应改为专用抓包组。

如果缺少 `setcap/getcap`，Ubuntu 安装 `libcap2-bin` 后再运行脚本。

完成后直接以普通用户运行：

```bash
./build/netsniffer
```

## 3. 重新编译的影响

- 修改界面、显示逻辑、协议解析后，正常编译并启动即可，无需再次授权。
- 普通 `cmake --build build` 不覆盖 `/usr/local/libexec/netsniffer/` 中的安装副本。
- 修改 `src/helper/` 或通信协议后，需要重新运行安装脚本更新辅助程序。
- 仍可能被系统策略、容器限制或不支持 capabilities 的文件系统拒绝；这与编译文件替换导致权限丢失是不同问题。

## 4. 本机通信协议

所有整数使用大端序。一次 stdout 帧包含固定头部和载荷，stderr 不用于传输数据包。

| 头字段 | 字节数 | 内容 |
| --- | --- | --- |
| magic | 4 | ASCII `NSCP` |
| version | 2 | 当前为 1 |
| type | 2 | 1 就绪、2 数据包、3 错误 |
| payload length | 4 | 后续载荷字节数，最大 65551 |

载荷：

- 就绪：4 字节链路类型。
- 数据包：8 字节 Unix 微秒时间戳、4 字节捕获长度、4 字节原始长度，以及原始字节。
- 错误：不超过 4096 字节的 UTF-8 文本。

接收端处理拆帧和粘帧，检查版本、类型、长度及握手顺序。单包捕获上限为 65535 字节，等待 GUI 消费的队列上限为 2000 个包。

## 5. 停止与异常退出

- 正常停止：父进程关闭辅助程序 stdin，辅助程序退出捕获循环，RAII 关闭 libpcap。
- 无流量：非阻塞读取与短轮询保证停止不依赖下一个包。
- 输出拥塞：非阻塞写入同时检查 stdin，停止请求不会被满管道永久阻塞。
- GUI 崩溃：管道关闭及 Linux 父进程死亡信号使辅助程序退出。
- 辅助程序不响应：父进程在停止超过 1 秒后发送终止信号，超过 2 秒后强制结束。
- 辅助程序异常退出、版本不兼容或无效数据：报告错误并恢复可重试状态。

## 6. 验证

不需要抓包权限的通信与错误测试：

```bash
ctest --test-dir build --output-on-failure
```

安装后，以普通用户执行真实回环抓包测试：

```bash
./build/capture_check
```

它使用固定安装路径，通过普通用户界面所使用的同一套 IPC 验证收包、三轮启停、空闲停止和不存在设备的错误处理。末尾的不存在设备错误是预期结果，进程退出码应为 0。

未安装时若只验证构建目录里的辅助程序，可以指定 `--helper` 路径。该参数仅用于测试工具；未授予权限的构建副本通常无法打开真实网卡。

验证权限分离：

```bash
getcap ./build/netsniffer
getcap /usr/local/libexec/netsniffer/netsniffer-capture
```

第一条应无输出；第二条应只包含 `cap_net_raw=ep`。最后再次构建 GUI，并以普通用户运行回环测试，确认安装副本不受重新编译影响。
