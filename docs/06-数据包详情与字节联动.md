# 数据包详情与字节联动

## 已实现的界面

主界面使用可拖动的垂直分隔条分成三个区域：

1. 包列表与选中包的完整摘要。
2. 协议详情树，按帧、链路层、网络层、传输层及载荷分组。
3. 原始字节区，每行显示偏移、16 个十六进制字节和对应 ASCII。

选中包后可以展开协议组查看字段；选中有字节范围的字段时，十六进制与 ASCII 同时高亮。捕获时间、捕获长度等元数据没有包内字节范围，选择时清除字节高亮。不可打印字节显示为点，不作为换行或控制字符执行。

界面只展示操作控件和数据，不添加开发步骤或讲解型提示。

## 解析器的字段信息

`src/parser/packetparser.h` 新增 `ProtocolField`：

- `name`、`value`：字段名称与已格式化的值。
- `offset`、`length`：从原始捕获字节起点计算的范围。
- `children`：协议分组下的字段。
- `offset = -1` 表示元数据，没有对应的原始字节。

列表解析继续使用 `parsePacket(packet)`，不保留详情树。只有查看选中包时调用 `parsePacket(packet, true)`，从同一份原始数据产生字段与范围，避免列表解析和详情解析各自维护协议偏移。

支持的详情包括：

| 协议 | 主要字段 |
| --- | --- |
| Ethernet / VLAN | MAC 地址、EtherType、VLAN ID、优先级、DEI |
| SLL / SLL2 / Loopback | 链路类型相关字段、接口编号或地址族 |
| IPv4 | 版本、头长、DSCP/ECN、总长、标识、分片、TTL、协议、地址、原始校验和、选项 |
| IPv6 | 版本、流量类别、流标签、载荷长度、下一头部、跳数、地址、已支持扩展头 |
| TCP | 端口、序列号、确认号、头长、标志、原始窗口字段、校验和、紧急指针、选项、载荷 |
| UDP | 端口、报文长度、校验和、载荷 |
| ICMP / ICMPv6 | 类型、代码、校验和、回显标识符和序号、可见数据 |
| ARP | 地址格式、操作码、发送方与目标的 MAC/IP |

字段中的校验和只显示原始值，不表示已验证。TCP 窗口显示未缩放的头部字段。位字段高亮其所在字节，不做单个位的颜色区分。

## 原始数据缓存

`MainWindow` 使用稳定包编号建立原始数据与表格项的映射。查看详情时从编号查找记录，不使用当前行号作为包的身份。

- 最多保留 2000 个包。
- 同时限制原始字节总量为 64 MiB；达到任一上限时淘汰最早收到的记录。
- 这只是原始字节缓存上限，不代表进程总内存上限。
- 被选中的包若被淘汰，清除选择、详情、摘要和原始字节，防止残留数据被误认为新包。
- 停止抓包保留缓存，仍可查看已捕获数据；再次开始则清空旧会话。
- 批量插入和淘汰期间抑制中间选择事件，完成后只按最终稳定编号更新一次详情。

当前仍使用 `QTableWidget`，这些约束也为后续替换为表格模型、加入过滤提供基础。

## 代码位置

- `src/parser/packetparser.*`：字段内容、协议分组和原始字节范围。
- `src/ui/packetbytesview.*`：Hex/ASCII 排版、跨行范围高亮。
- `src/ui/mainwindow.*`：三窗格、包缓存、选择与字段联动。
- `tests/parser_check.cpp`：已知字段位置、可变头长、VLAN/扩展头及随机输入范围检查。
- `tests/packet_details_check.cpp`：界面联动、跨行高亮、非打印字节、排序、停止/重启、2000 包及 64 MiB 淘汰验证。

## 构建和验证

```bash
cmake -S . -B build
cmake --build build -j2
ctest --test-dir build --output-on-failure
./build/netsniffer
```

本阶段没有修改抓包辅助程序或 IPC 协议，不需要重新安装或重新授予抓包权限。

自动测试使用合成包验证对应关系，不需要抓包权限。开发中还执行了 AddressSanitizer/UndefinedBehaviorSanitizer 检查，并生成离屏界面预览检查三窗格布局。
