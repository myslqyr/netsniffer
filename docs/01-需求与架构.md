# 01 需求与架构

## 1. 功能范围

| 优先级 | 功能 | 完成表现 |
| --- | --- | --- |
| P0 | 网卡枚举与实时抓包 | 选择网卡后能持续捕获真实流量，支持停止和再次启动 |
| P0 | 图形界面 | 包列表、协议详情树、原始字节区能够联动 |
| P0 | 基础解析 | 能解析 IPv4、IPv6、TCP、UDP、ICMP、ICMPv6；补充 Ethernet、ARP |
| P0 | 协议筛选 | 能筛选 HTTP、TCP、UDP、IPv4、IPv6、ICMP 类流量 |
| P0 | 稳定性 | 截断包、未知协议、错误过滤表达式不会使程序崩溃 |
| P1 | 应用层分析 | 识别明文 HTTP/1.x，展示请求方法、目标、状态码等；可补充 DNS |
| P1 | PCAP 文件读写 | 抓包结果可保存，文件可重新加载并分析 |
| P1 | TCP 流追踪 | 双向连接归组；进一步按序列号重组并展示字节流 |
| P2 | 进程关联 | 显示本机连接对应的 PID/进程名，并明确无法匹配的情况 |
| P2 | 统计与图表 | 协议占比、吞吐量、连接统计、握手时序 |

这里的 P0/P1/P2 是开发优先级，不是教师公布的评分细则。课程明确将流追踪列为加分项。

## 2. 初版边界

- 面向本机普通网络流量分析，不承诺在交换网络中捕获其他机器的全部通信。
- HTTP 首先支持明文 HTTP/1.x；HTTPS 显示 TLS/加密流量信息，不承诺解密。HTTP/2、HTTP/3 后续扩展。
- 初版识别 IP 分片并显示分片信息，非首片不误解析为传输层；完整 IP 重组作为后续扩展。
- IPv6 按长度遍历已支持的扩展头；未知扩展头停止深入解析并保留原始数据。
- 首先支持 Ethernet 网卡；Linux cooked capture、loopback 等必须按链路类型适配，未支持时明确提示，不能套用 Ethernet 头。
- 首版使用 libpcap，无需自行开发 Netfilter hook 或 eBPF 程序。

## 4. 数据流与线程

```text
GUI 配置 → 抓包线程 → 复制原始包 → 解析/连接归组 → 有界结果队列
                                                        ↓
PCAP 文件 → 离线读取与解析                         GUI 定时批量刷新
                                                        ↓
                                             包列表 / 字段树 / Hex
```

- GUI 线程只负责显示和用户操作，不执行阻塞抓包。
- 初版可在抓包工作线程中顺序解析；出现性能瓶颈后再拆分线程，避免先引入多线程乱序问题。
- 队列、缓存和流重组缓冲都设置上限。区分网卡捕获丢包、应用队列丢弃、缓存淘汰三个指标。
- `pcap_t` 的设置、读取、关闭统一由拥有它的线程执行。停止流程通过停止标志配合适合平台的有界等待或唤醒机制退出，不能依赖一定会有下一个包到来。
- 工作线程结束并等待完成后，再销毁窗口与抓包资源。GUI 的“停止”不能阻塞主线程无限等待。

## 5. 数据结构约定

### RawPacket：原始事实

- 全局包 ID、会话 ID。
- 时间戳及其精度；离线数据不能把纳秒误当成微秒。
- `capturedLength`：实际持有的字节数。
- `originalLength`：线上原始包长度。
- `linkType`：由 `pcap_datalink()` 获取。
- `bytes`：自己持有的字节数组，不保存 libpcap 临时指针。

### ParsedPacket：分析结果

- 源/目的 MAC、IP、端口，采用可选字段，不存在时保持为空。
- 协议集合，如 `{Ethernet, IPv4, TCP, HTTP}`；用于分层筛选。
- 列表摘要和详情字段树。
- 每个字段的字节偏移和长度，用于 Hex 高亮。
- 解析状态：完整、捕获截断、格式异常、暂不支持。
- 可选连接 ID；不能靠列表行号引用包，排序和筛选后行号会变化。

### Flow：连接信息

- 传输协议与规范化的两端地址/端口，IPv4 与 IPv6 类型明确区分。
- 保留 A→B、B→A 两个方向，以及各自的序列号和重组状态。
- 首末时间、包数、字节数、连接状态。
- 对相同五元组的后续新连接，通过握手、关闭状态与超时区分连接实例。

## 6. 模块职责

| 模块 | 输入 | 输出 | 关键约束 |
| --- | --- | --- | --- |
| CaptureEngine | 网卡、捕获配置、BPF | RawPacket、统计、错误 | RAII 释放句柄，退出可控 |
| PacketParser | RawPacket | ParsedPacket | 按实际字节检查边界，未知协议可降级 |
| DisplayFilter | 筛选条件、ParsedPacket | 是否显示 | 不修改原始包存储 |
| FlowTracker | TCP/UDP 元数据 | 连接 ID、统计 | 双向归组，区分连接实例 |
| TcpReassembler | TCP 序列号、载荷、标志 | 两个方向的连续字节及缺口 | 处理乱序、重复、资源上限 |
| PcapStorage | 原始包与元数据/文件 | PCAP 文件/RawPacket | 保留链路类型、时间精度和长度 |
| PacketTableModel | 包 ID 与可见记录 | Qt 表格数据 | 批量插入，避免逐包创建控件 |

## 7. 过滤的设计

捕获过滤使用 libpcap 的 BPF 语法，如 `tcp and port 80`。它影响后续捕获，已经排除的数据无法事后恢复。

显示过滤针对已保存的解析结果。第一版使用协议下拉框、IP 输入框、端口输入框，多个条件采用 AND；同一协议框可以选择一种协议。不要直接承诺兼容 Wireshark 的完整显示过滤语言。

HTTP 按内容和连接上下文识别，不能仅凭 80 端口标记。流重组后识别出的 HTTP，应更新该连接相关记录；无法定位单个包时，界面明确显示“此连接含 HTTP”，避免把流级结论当成每个包都有 HTTP 报头。
