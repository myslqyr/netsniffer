# 显示过滤与捕获过滤

## 使用方法

### 显示过滤

在界面选择协议，并按需填写 IP 地址和端口，然后点击“应用”。协议下拉框切换后立即应用；IP/端口输入后也可按回车应用。

- 支持 TCP、UDP、IPv4、IPv6、ICMP、ICMPv6、ARP、IGMP。
- 同时填写的条件采用 AND：协议、IP、端口必须都匹配。
- IP 匹配源地址或目的地址，接受完整 IPv4/IPv6 地址；IPv6 按地址值比较，压缩与展开写法等价。
- 端口匹配源端口或目的端口，范围为 0–65535。
- IP 和端口分别匹配任意一端，并不要求它们属于同一个端点。例如源 IP 和目的端口可以共同满足条件。
- 当前 IP 条件不接受 CIDR、地址范围或带接口作用域的写法。
- “清除”只清除显示条件，恢复当前缓存中仍保留的包。
- 输入错误时显示错误信息，保留上一次有效条件和对应结果。

协议按解析层次匹配。例如同一个 IPv4/TCP 包既匹配 TCP，也匹配 IPv4。仅识别出网络层的非首片不虚构端口。ARP 的已解析发送方/目标 IP 也可以匹配 IP 条件。

显示过滤不会停止抓包，也不会删除不匹配的缓存记录。所有缓存包共同受 2000 包和 64 MiB 原始字节上限约束，清除条件无法恢复已经淘汰的包。

### 捕获过滤

开始前在“捕获过滤”中输入 libpcap 的 BPF 表达式，留空则不过滤。例如：

```text
tcp
udp port 5353
host 192.168.1.10
tcp and (port 80 or port 443)
ip6 and udp
```

捕获期间输入框锁定，停止后可以修改，再次开始时生效。辅助程序先打开设备、放弃运行中的 capabilities，然后编译和安装 BPF，成功后才发送就绪消息和数据包。

不匹配捕获条件的数据不会进入 GUI 缓存，清除显示过滤无法恢复这些数据。BPF 按捕获接口的实际链路类型编译，适用时使用该接口网掩码；无法获取网掩码时使用 `PCAP_NETMASK_UNKNOWN`，依赖有效掩码的表达式可能返回具体编译错误。

HTTP 内容识别仍属于后续应用层分析工作，界面没有通过端口直接将流量归类为 HTTP。

## 本次需要更新辅助程序

辅助程序新增了可选的 `--filter` 参数，因此需要更新安装副本一次：

```bash
cmake -S . -B build
cmake --build build -j2
sudo bash scripts/install-capture-helper.sh
./build/netsniffer
```

后续只修改 GUI 或显示过滤逻辑时，依然不需要重新授权。尚未更新的旧辅助程序仍可在捕获条件留空时运行；传入捕获条件时，GUI 会报告辅助程序需要更新。

## 实现

- `src/filter/displayfilter.*`：协议、IP、端口条件校验与匹配。IP 使用二进制地址归一化，端口保留“未提供”和数值 0 的区别。
- `MainWindow`：缓存解析摘要，按稳定包编号判断可见性；隐藏行而非删除记录。排序后重新按编号应用可见性。
- 选中包被隐藏时清除详情、原始字节和高亮；仍匹配的选中包保留详情。停止后仍可筛选缓存。
- 状态栏分别展示接收数、缓存数、显示数与队列丢弃数。
- `CaptureWorker`：通过 QProcess 独立参数传递 BPF 文本，不经过 shell。表达式 UTF-8 长度最多 4096 字节，拒绝内嵌 NUL。
- `src/capture/capturefilter.*`：封装 BPF 编译、安装和资源释放；编译失败不复用旧指令。
- 辅助程序新增 `--interface <设备> --filter <表达式>` 调用方式；已有二进制帧格式保持版本 1。

## 验证

```bash
ctest --test-dir build --output-on-failure
```

自动测试覆盖：

- 显示条件的 AND 组合、协议层次、地址两端匹配、IPv6 归一化、端口 0、错误输入。
- 使用真实 libpcap BPF 编译器和离线包验证 TCP/UDP/IPv6、IP、端口与逻辑表达式。
- 通过同一套进程管道传递带空格/括号的表达式，并在合成数据源中执行 BPF 后交给 GUI。
- 过滤后的详情对应、排序、无结果、清除恢复、停止后筛选、实时到包和缓存淘汰。
- BPF 错误后重试、旧辅助程序更新提示、捕获时锁定条件输入。

这些自动测试不打开真实网卡。辅助程序更新后，可以普通用户运行真实回环测试：

```bash
./build/capture_check --filter 'udp port 43891'
```

测试会产生指定端口的 UDP 流量，验证实际收包、三轮启停与空闲停止；最后不存在设备的错误属于预期测试。进程最终退出码应为 0。
